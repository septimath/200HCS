Проект · MVP за 12 часов

PhishGuard — пассивный анализ фишинговых писем

Веб-приложение: загружаешь письмо .eml — получаешь оценку риска от 0 до 100, список сработавших признаков и таблицу IOC. Вложения не открываются, по ссылкам не переходим, вердикт объясним. MVP собирается за 12 часов и работает без API-ключей.

Что делает система

01

Разбирает письмо

Заголовки From, Reply-To, Return-Path, Subject, Authentication-Results; текстовое или HTML-тело; вложения — только имя, размер и SHA-256. Ничего не исполняется.

02

Достаёт IOC

URL из текста и HTML, домены, e-mail, IP. Нормализует регистр, punycode и обрезает tracking-параметры, чтобы один адрес не считался дважды.

03

Проверяет признаки

Возраст домена через RDAP, репутация URL в URLhaus, результат SPF/DKIM/DMARC из заголовков, похожесть домена на популярный, punycode, ссылка на IP, слова срочности.

04

Считает риск

Каждый признак даёт баллы, сумма ограничена 100. Порог: 60+ — красный, 30–59 — жёлтый, меньше 30 — зелёный. Это риск-балл, а не «вероятность».

05

Объясняет

Таблица «признак — баллы — что нашли», рекомендации и JSON-отчёт. Человек видит, почему вердикт такой, и может проверить каждый пункт руками.

Архитектура

Пять модулей, один поток данных. Внешние запросы — только на шаге проверок и только по домену или URL; тело письма и вложения наружу не уходят.

Сборка за шесть вечеров

01

Парсер · 2 ч

Читает .eml, печатает From / Reply-To / Return-Path / Subject / Authentication-Results, декодирует заголовки, достаёт тело и вложения. Готово, если три разных письма разбираются без ошибок.

02

IOC · 2 ч

URL из текста и HTML, домены, дедупликация, нормализация. Готово, если на письме с 10 ссылками нет дублей и мусора в конце адреса.

03

Проверки · 2 ч

RDAP с таймаутом и кэшем, URLhaus, разбор Authentication-Results, Левенштейн. Готово, если каждая проверка возвращает значение или «неизвестно», а не падает.

04

Скоринг · 2 ч

Таблица весов, сумма, порог, объяснение. Готово, если один и тот же файл даёт один и тот же результат при включённой и выключенной сети (кроме сетевых признаков).

05

Интерфейс · 2 ч

Streamlit: загрузка, светофор, таблица признаков, ссылки, вложения, кнопка JSON. Готово, если демо проходит за две минуты без консоли.

06

Тесты · 2 ч

20 писем (10 фишинг / 10 легитимных), precision/recall, README, скриншоты. Готово, если цифры посчитаны и ограничения описаны.

import hashlib, html, json, re
from datetime import datetime, timezone
from email import policy
from email.parser import BytesParser
from urllib.parse import urlparse
import requests
import streamlit as st

POPULAR = {"google.com", "yandex.ru", "sberbank.ru", "vtb.ru",
           "mail.ru", "gosuslugi.ru", "github.com", "microsoft.com"}
URGENCY = ("срочно", "немедленно", "заблокирован", "подтвердите",
           "оплатите", "аккаунт", "пароль", "в течение 24")
URL_RE = re.compile(r"https?://[^\s<>\"')]+", re.I)

def parse_eml(data):
    msg = BytesParser(policy=policy.default).parsebytes(data)
    body = ""
    part = msg.get_body(preferencelist=("plain", "html"))
    if part is not None:
        body = part.get_content()
        if part.get_content_type() == "text/html":
            body = html.unescape(re.sub(r"<[^>]+>", " ", body))
    atts = []
    for a in msg.iter_attachments():
        try:
            payload = a.get_content()
            if isinstance(payload, str):
                payload = payload.encode("utf-8", "ignore")
            atts.append({"name": a.get_filename() or "noname",
                         "size": len(payload),
                         "sha256": hashlib.sha256(payload).hexdigest()})
        except Exception:
            continue
    return {"from": str(msg["From"] or ""),
            "reply_to": str(msg["Reply-To"] or ""),
            "return_path": str(msg["Return-Path"] or ""),
            "subject": str(msg["Subject"] or ""),
            "auth": str(msg["Authentication-Results"] or ""),
            "text": body, "attachments": atts}

def extract(text):
    out, seen = [], set()
    for raw in URL_RE.findall(text):
        url = html.unescape(raw).rstrip(".,;:)")
        if url in seen:
            continue
        seen.add(url)
        host = (urlparse(url).hostname or "").lower()
        out.append({"url": url, "host": host})
    return out

def domain_of(header):
    m = re.search(r"@([\w.-]+)", header or "")
    return m.group(1).lower() if m else ""

@st.cache_data(ttl=86400, show_spinner=False)
def age_days(host):
    try:
        r = requests.get(f"https://rdap.org/domain/{host}", timeout=5)
        events = r.json().get("events", [])
        reg = next((e["eventDate"] for e in events
                    if e.get("eventAction") == "registration"), None)
        if not reg:
            return None
        dt = datetime.fromisoformat(reg.replace("Z", "+00:00"))
        return (datetime.now(timezone.utc) - dt).days
    except Exception:
        return None

@st.cache_data(ttl=3600, show_spinner=False)
def in_urlhaus(url):
    try:
        r = requests.post("https://urlhaus-api.abuse.ch/v1/url/",
                          data={"url": url}, timeout=5)
        j = r.json()
        return j.get("query_status") == "ok" and j.get("url_status") == "online"
    except Exception:
        return None

def levenshtein(a, b):
    prev = list(range(len(b) + 1))
    for i, ca in enumerate(a, 1):
        cur = [i]
        for j, cb in enumerate(b, 1):
            cur.append(min(prev[j] + 1, cur[j - 1] + 1,
                           prev[j - 1] + (ca != cb)))
        prev = cur
    return prev[-1]

def score(email, urls, online):
    findings = []
    def add(code, label, points, evidence):
        findings.append({"code": code, "label": label,
                         "points": points, "evidence": evidence})
    frm, rep = domain_of(email["from"]), domain_of(email["reply_to"])
    if rep and frm and rep != frm:
        add("reply_to", "Reply-To на другом домене", 20, f"{frm} → {rep}")
    rp = domain_of(email["return_path"])
    if rp and frm and rp != frm:
        add("return_path", "Return-Path на другом домене", 10, f"{frm} → {rp}")
    auth = email["auth"].lower()
    if "spf=fail" in auth or "dkim=fail" in auth or "dmarc=fail" in auth:
        add("auth", "SPF/DKIM/DMARC fail", 15, email["auth"][:140])
    if all(x in auth for x in ("spf=pass", "dkim=pass", "dmarc=pass")):
        add("auth_ok", "SPF/DKIM/DMARC pass", -20, "все три прошли")
    hits = [w for w in URGENCY if w in email["text"].lower()]
    if len(hits) >= 2:
        add("urgency", "Давление на срочность", 5, ", ".join(hits[:4]))
    for u in urls[:5]:
        host = u["host"]
        if not host:
            continue
        if "xn--" in host:
            add("punycode", "Punycode-домен", 10, host)
        if re.fullmatch(r"\d{1,3}(\.\d{1,3}){3}", host):
            add("ip_link", "Ссылка на IP", 10, host)
        for p in POPULAR:
            if host != p and host.endswith(p.split(".")[-1]) and levenshtein(host, p) <= 2:
                add("lookalike", "Похожий домен", 10, f"{host} ~ {p}")
                break
        if online:
            if in_urlhaus(u["url"]):
                add("urlhaus", "URL в URLhaus", 30, u["url"])
            age = age_days(host)
            if age is not None and age < 30:
                add("age", "Домен моложе 30 дней", 25, f"{host}: {age} дн.")
    total = max(0, min(100, sum(f["points"] for f in findings)))
    return total, findings

st.set_page_config(page_title="PhishGuard", page_icon="🛡", layout="wide")
st.title("PhishGuard")
st.caption("Пассивный анализ .eml: без открытия вложений и переходов по ссылкам")

online = st.toggle("Проверять репутацию в сети", value=True)

if up:
    email = parse_eml(up.read())
    urls = extract(email["text"])
    total, findings = score(email, urls, online)
    level = "красный" if total >= 60 else "жёлтый" if total >= 30 else "зелёный"
    st.metric("Риск", f"{total}/100", level)
    st.progress(total / 100)
    st.subheader("Признаки")
    st.dataframe(findings or [{"label": "Признаков не найдено", "points": 0}],
                 use_container_width=True)
    st.subheader("Ссылки и вложения")
    st.dataframe(urls, use_container_width=True)
    st.dataframe(email["attachments"], use_container_width=True)
    report = {"email": {k: v for k, v in email.items() if k != "text"},
              "urls": urls, "findings": findings,
              "score": total, "level": level}
    st.download_button("Скачать отчёт JSON",
                       json.dumps(report, ensure_ascii=False, indent=2),
                       "phishguard.json", "application/json")

Тест и метрики

20 писем: 10 фишинговых и 10 легитимных. Считаешь матрицу ошибок и две цифры: precision — доля настоящих фишингов среди тех, что система отметила красным; recall — доля найденных фишингов среди всех фишинговых. На маленькой выборке это ориентир, и в отчёте это надо сказать прямо.

Что меряемЦельКак проверять
Recall≥ 0,8Из 10 фишинговых красным или жёлтым отмечено 8+
Precision≥ 0,7Из всех «красных» не больше 30% ложных
Скорость< 2 сБез сетевых проверок; с сетью — до 10 с
Офлайн100%Выключить сеть — приложение работает, сетевые признаки помечены «неизвестно»

Фишинг — самый частый вход в атаку. Сотрудник не обязан быть аналитиком, а служба поддержки не успевает разбирать каждое письмо руками.

02

Загружаешь обычное письмо: домен старый, SPF/DKIM/DMARC pass, ссылок на подозрительные домены нет. Вердикт зелёный, объяснение прозрачное.

03

Красное письмо · 80 с

«Аккаунт заблокирован», домен 2 дня, Reply-To на другом домене, URL в URLhaus. Показываешь 89/100 и таблицу: за что именно.

04

Офлайн · 50 с

Выключаешь сеть, повторяешь анализ: вердикт сохраняется по локальным признакам, сетевые помечены «неизвестно». Это ответ на «а если интернета не будет».

05

Как устроено · 90 с

Пять модулей, поток данных, где считается балл. Подчёркиваешь: LLM не принимает решение, вердикт детерминирован.

06

Право и ограничения · 50 с

Вложения не открываются, по ссылкам не ходим, только публичные реестры. Честно про .msg, OCR и маленькую выборку.

07

Цифры и развитие · 60 с

Precision/recall на 20 письмах, скорость, что дальше: шлюз, локальная модель, расширение.

Ограничения и правовая рамка

  • Пассивность. Вложения не исполняются, по ссылкам браузер не переходит, письма никуда не отправляются. Анализируется уже полученный образец.
  • Только публичные источники. RDAP и URLhaus — открытые реестры; запросы идут по домену или URL, без тела письма и вложений.
  • Данные остаются у пользователя. Есть режим без сети: приложение работает локально, отчёт не уходит наружу.
  • Ограничения MVP. Только .eml, без OCR картинок и без детонации вложений; выборка 20 писем; балл — не вероятность. URLhaus может требовать бесплатный ключ — без него признак помечается «неизвестно», а не «чисто».
  • Формулировка для жюри. «Пассивный анализ образца без взаимодействия с инфраструктурой атакующего — blue-team-подход, согласованный с NIST SP 800-61».

Вопросы экзаменаторов

18 ответов, которые лучше выучить своими словами. Все они про то, что реально сделано, а не про «перспективы».

Почему это проект по информационной безопасности, а не по вебу?

Задача — обнаружить фишинг, то есть защитить пользователя. Веб здесь только способ доставки: разбираются заголовки, ссылки и признаки подделки, а результат — решение о риске. Это классический blue-team-сценарий: анализ уже полученного образца без взаимодействия с атакующим.

В чём новизна? Таких сервисов много.

Новизна не в «ещё одном антивирусе», а в сочетании трёх свойств: письмо не покидает машину, вердикт объясним по каждому признаку, система работает офлайн. Большинство публичных проверок — чёрный ящик, который отправляет письмо на сторонний сервер; здесь наоборот.

Как работает система от загрузки до вердикта?

Пять шагов: разбор MIME → извлечение IOC → проверки (RDAP, URLhaus, Authentication-Results, похожесть домена) → сумма весов с порогом → отчёт с объяснением. Каждый шаг — отдельный модуль, поэтому его можно заменить или протестировать отдельно.

Где здесь искусственный интеллект?

В MVP его нет — и это осознанно. Вердикт считает детерминированный движок, поэтому результат воспроизводим. LLM можно подключить как необязательный слой, который переписывает готовое объяснение человеческим языком; решение она не принимает и вложений не видит. Если ключа или сети нет, система просто работает без этого слоя.

Почему не машинное обучение?

Нет размеченного датасета и нет необходимости: на 20 письмах модель переобучится и её нельзя будет объяснить. Правила дают прозрачный baseline, который можно проверить руками. ML — следующий шаг, когда появится хотя бы несколько сотен размеченных образцов и метрики станут устойчивыми.

Как вы проверяли точность?

Собрал 20 писем: 10 фишинговых и 10 легитимных. Считаю precision, recall и матрицу ошибок, отдельно смотрю, на каких признаках система ошибается. Цель — recall не ниже 0,8 при precision не ниже 0,7. Выборка маленькая, поэтому в отчёте это указано как ограничение, а не как гарантия.

Что будет при ложном срабатывании?

Человек видит каждый признак и его вклад, поэтому может проверить: действительно ли домен новый, действительно ли ссылка в URLhaus. Жёлтая зона специально сделана зоной ручной проверки. Порог и веса можно менять после калибровки, не меняя код проверок.

Чем это отличается от VirusTotal и антивируса?

Антивирус ищет сигнатуры файлов, VirusTotal — репутацию по базам. Мой инструмент анализирует контекст письма: несовпадение адресов, результат аутентификации домена, возраст ссылки, давление на срочность. Это дополнение к антивирусу, а не замена; при желании VT можно подключить по хешу вложения, но для MVP это не нужно.

Безопасно ли загружать письмо? Что с персональными данными?

Письмо обрабатывается локально, вложения не открываются и не исполняются. В сеть уходят только домен для RDAP и URL для URLhaus — без тела письма, без вложений и без адресов получателей. В офлайн-режиме не уходит ничего; отчёт можно скачать локально.

Почему Streamlit, а не нормальный фронтенд?

Streamlit даёт работающий интерфейс за вечер и не отвлекает от логики анализа — это правильный выбор для прототипа и демо. В продакшене интерфейс заменится на FastAPI плюс отдельный фронтенд, но ядро анализа останется тем же.

Как это масштабировать на поток писем?

Вынести проверки в отдельный сервис с очередью, кэшировать ответы RDAP и URLhaus, ограничить таймауты и число проверяемых ссылок на письмо. Тогда анализ одного письма — это несколько параллельных запросов, а не блокирующая операция.

Что было самым сложным?

Парсинг MIME: multipart, разные кодировки, письма только с HTML, вложения разных типов. Второе — нормализация URL: punycode, сущности HTML, мусор в конце адреса. Оба места закрыты тестами на реальных письмах.

Почему домен моложе 30 дней считается признаком?

Это эмпирическое правило: фишинговые домены часто регистрируют под кампанию и живут недолго. Но это только один признак и только баллы: старый домен не гарантирует безопасность, а новый — не гарантирует атаку. Если RDAP не ответил, ставится «неизвестно», а не «чисто».

Что если письмо на русском или с картинкой вместо текста?

Текст извлекается из HTML, русская лексика срочности есть в словаре. Картинки в MVP не распознаются — это ограничение, которое я озвучиваю честно; OCR и анализ изображений — следующий шаг. Для писем без текста работают заголовки и ссылки, то есть часть проверок всё равно сработает.

Как защищено само приложение?

Ограничение размера файла, таймауты на внешние запросы, запрет исполнения вложений, отсутствие перехода по ссылкам (значит, нет SSRF через редиректы), проверка домена перед запросом в RDAP. Отчёт не содержит тела письма — только метаданные и IOC.

Почему оценка 0–100, а не вероятность?

Потому что это риск-балл, а не статистическая вероятность: я не обучал модель на вероятностях и не могу честно сказать «73%». Балл показывает, сколько признаков сработало и насколько они весомы. Порог 60 — красный, 30–59 — жёлтый; это написано и в интерфейсе, и в отчёте.

Юридически это законно?

Да: анализируется уже полученное письмо, без взаимодействия с инфраструктурой атакующего. Используются публичные реестры, вложения не исполняются, данные не передаются третьим лицам. Это соответствует практике blue team и рекомендациям NIST SP 800-61 по обращению с инцидентами.

Что дальше?

Три направления: интеграция с почтовым шлюзом (анализ на лету), локальная модель на размеченных данных и OCR вложений. Браузерное расширение — отдельный проект, в MVP его нет, чтобы не размывать фокус.

Режим

Без выходных — это 59 дней подряд. Такое выдерживает только тот, кто спит и не пытается «догнать» пропущенное двойной нагрузкой.

  • Сон 8 часов. Недосып стоит дороже одного пропущенного вечера: на туре он превращает лёгкие задачи в нерешённые.
  • 25 минут сам. Нет продвижения — отложи и вернись. Подсказку бери только после честной попытки, готовое решение — в последнюю очередь.
  • Тренируйся без интернета. На туре не будет ни поиска, ни заметок. Только help(), dir() и man.
  • Пиши одну строку после задачи. «Этот приём нужен для…» — иначе через неделю всё сливается в кашу.
  • Не удваивай. Пропустил день — перенеси темы на резервные часы в субботу, а не сиди шесть часов подряд.
  • 1 января — 3 часа теории. Это самый лёгкий день в плане; остальное время отдыхай, чтобы не сорваться на второй неделе.
  • OSINT — после региона. В темах региона его нет, поэтому в 195 часов он не входит. Если захочется отдохнуть с пользой — оставь на выходной после 24 января.

Как проходить день с другим ИИ

Скопируй тему и пункты дня из календаря и отправь так:

Тема: <дата и название>. План: <пункты>. Объясни по порядку, потом дай 3 задачи по теме и проверь мои решения. Готовых ответов не давай, только подсказки после попытки.

Так день не превращается в чтение: ты заканчиваешь его решёнными задачами, а не «вроде понял».

Что считать закрытым днём

Не «прочитал», а: можешь без подсказки объяснить тему вслух, написал рабочий скрипт или решил задачу, записал одну строку вывода. Если нет — день не закрыт, даже если часы отсижены.
